# 协议原始指标、未来帧与集成流

## 指标逐字段合并

`protocol_metrics` 按字段合并，不再用REST比较费率的字典整体覆盖WS当前预估/上次结算指标（反之亦然）。每个字段保留独立的 `protocol_metric_sources`、`protocol_metric_timestamps`、`protocol_metric_received_at`。来自该次实际patch的字段才更新自己的来源/时间；价格更新、空字典和缺省字段不续期旧指标。

`cleared_protocol_metrics` 表示明确删除。来源不匹配时不能删除另一个来源的字段；删除时刻保留在元数据中，重启后旧/同观察时间的指标不能复活。来源时间未知时仅用该字段的接收顺序决定更新，仍把来源时间标为未知。Lighter明确null/无效字段会清对应原始值；结算时间无效或单位不明时也清派生毫秒时间，不留旧alias。缺字段不等于删除。单位未验证的值仍是原始指标，不升级为规范化资金费或收益输入。

旧缓存若无逐字段来源信息，只能标 `legacy_field_provenance_unavailable`、时间未知；不能借旧snapshot总时间推断，因为它可能属于之后的价格更新。

## 未来帧

Hyperliquid排序水位只接受不晚于当前本地时刻及该帧接收时刻的源时间，取消此前30秒宽容对水位的影响。collector也不让未来时间的旧缓存阻止后续正常报价；即使墙钟后来追上原异常时间，仍核对当时接收时刻，不恢复该异常的排序权重。源时间原值保留；扫描时仍拒绝未来字段，未把异常时间钳制成当前时间。回归覆盖+1ms、+20s、+40s之后正常行情、重启、原始指标和删除记录。

## 集成负载证据与限制

见 [selection隔离测量](evidence/stream-selection-load.json)：347市场、3000patch、300/s、约10秒，signature检查3001→10次，CPU4.860→0.543秒。最大timer lag反而14.311→67.963ms，完整保留。此测量排除了merge、写盘和网络，不证明实网断流根因。

另见 [合并/持久化负载](evidence/stream-integration-load.json)：347市场、4500patch、300/s，真实merge与SQLite历史写入、独立排队生产者、一次注入ConnectionError及真实5秒退避。4500条均处理、重连一次，最后347市场双边报价通过新鲜度检查；队列峰值1504，最大处理间隔5.008秒。该记录期间完整pytest在同一工作区并行运行，没有CPU隔离；不是专用机器延迟基准。未包括真实WS解码/网络、其他平台采集、HTTP和浏览器推送，不能复现或排除父线程所报真实应用断流。

目录/设置/metadata签名至多每秒检查一次；热流、无消息时都检查，等待接收返回后也先核对，避免停用后继续套用旧订阅消息。每条patch使用集合身份检查。本地处理时刻、处理间隔、累计数量、错误类型及时间用于追查，不称网络延迟。仍需外部实测获取断线类型、源端响应、队列/循环负载和覆盖的同步轨迹。
