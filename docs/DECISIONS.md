# 技术决策

1. 复用成熟 CCXT 处理 CEX 公共 API、动态限流与原始字段；自行保留合约乘数、费率周期、事件时间与平台身份，不把统一 ticker 当作资产身份证明。
2. 默认只确认 BTC/ETH/SOL 的明确原生身份。其余资产保持命名空间隔离，提供人工确认审计。包装资产不自动等同原生资产。
3. 不使用 USDT/USDC/USD 1:1 隐式换算；计算要求显式有来源的汇率。未知资金费周期不归一化。
4. 原生 API 无法实时访问时依据官方文档和 SDK 实现、使用样本测试，在线验证时间保持空；实现完成不等于接入验收。
5. CEX 源 WS 作为 REST 价格采集的优先路径，两者逐字段时序合并；保留元数据/资金费 REST 补充与失败降级。DEX 源 WS 和更宽市场订阅后续补齐。
6. 所有可执行收益要求规模对应盘口或精确输入/输出路线；资金费情景与真实已结算值分开，费用来源与退出假设显式保存。
7. 本次用户明确要求通知使用模拟测试，真实机器人发送延期；没有真实凭证，没有向外部会话发送消息。
8. 使用本地磁盘与 SQLite 简化 Windows 安装；Linux 云环境验证不能冒充 Windows 实测。
9. 根 Agent 负责集成；开发 Agent 使用 gpt-6.1-sol/high，独立验收使用 gpt-6-astra/high。运行工具并发上限为主 Agent + 6 子 Agent，未超过用户允许数量。
