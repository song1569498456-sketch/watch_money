# 5秒刷新目标

新建数据目录或缺失对应配置项时，关注行情详细采集 `poll_seconds`、全目录价格采集 `broad_poll_seconds`、资金费采集 `funding_poll_seconds` 默认均为5秒，行情页面合并刷新 `refresh_ms` 默认5000毫秒。全目录价格与资金费由已有独立批量调度器执行，目标按整轮开始时刻计时；详细查询和不支持批量计划的来源还需计入请求耗时/轮转规模。

价差扫描及资金费专页默认每5秒读取后端最新数据，可以取消勾选暂停。上一请求未完成时跳过本次时钟，防止取消慢查询或堆积请求；筛选变化仍取消旧范围请求，返回页面立即重查。不活动页面与隐藏浏览器标签不自动轮询。资金费详情的历史请求不会被每5秒自动刷新取消，切换筛选或市场仍保持版本隔离。

行情仍保留WebSocket事件驱动及查询版本保护；断线后的HTTP回退和状态检查目标改为5秒，后台轮询不抢占未完成请求。行情源时间、接收时间、字段有效性、过期门槛、资金费结算周期全部保持原语义。CoinGecko身份目录和新市场目录发现不改为5秒。

## 已有设置

资产聚合的价差查询默认用最低 ask / 最高 bid 极值选择，避免每5秒枚举全部方向。
“所有方向”只在用户切换或点击刷新时请求明细，暂停其自动轮询；返回资产聚合后恢复原勾选状态。
资金费比较仍使用独立的费率口径。

同一筛选范围内的定时查询在后台更新，不插入、移除整块加载提示，也不反复切换整表按钮的禁用状态；现有行按稳定 ID 更新数值和排序，展开状态与滚动位置保留。筛选、设置或页面活动范围变化仍立即隔离旧请求；慢请求不重叠。过期时保留上次查询值并标为“排名待更新”，不再整表清空，同时继续禁止用过期结果发起测算。

扫描页“最大年龄”改为“最旧报价”：它是本资产组内本次查询通过校验的 bid/ask 字段中，最旧一项距今的时间，按源时间和接收时间较早者计算；不是刷新间隔，也不是允许的最大年龄。陈旧门槛仍由 `stale_seconds` 单独控制。

数据源范围和币种身份是不同条件。启用平台并打开广覆盖后才会采集其全目录；没有正式身份映射的市场仍保留原生身份、允许查看单市场行情，但不按同名自动进入跨平台比较。扫描页提供身份审核与 CEX/DEX 状态入口；官方证据的预览和明确批准流程保留。

数据库没有记录保存值是否由用户手动修改，因此**所有已有值均保留，不猜测并覆盖旧默认值**。例如已有30秒全目录采集仍保持30秒；扫描页每5秒查询并不会使该来源变成5秒采集。设置页提供“将四项刷新目标设为5秒（保存后生效）”，仅改草稿中的上述四项，用户保存后生效；其它平台开关、限流参数及身份更新配置不动。

## 实际限制

沿用CCXT/原生适配器的已审阅限流、批次预算、最短轮转估计和指数退避，不增加无界并发。来源诊断逐平台展示实际/估计整轮间隔；超过5秒明确提示。请求周期不能保证交易所每5秒发布新数据；资金费上游旧时间仍会过期，不改写时间或放宽阈值。逐市场回退的大目录、慢网络和访问限制可能无法达到目标。本次没有实网5秒覆盖验收，未访问受阻OKX WS或Lighter。

验证为受影响的默认配置/已有配置、采集调度、限流估计和设置缓存专项，以及真实本机HTTP浏览器测试：5秒扫描、7秒慢资金费请求不中断/不重叠、完成后继续查询、不活动页停止、手动暂停。浏览器输入为隔离合成市场，非真实交易所吞吐证明。证据见 `docs/evidence/browser-five-second-refresh.json`。
