# 可追溯资产审核包

`GET /api/assets/verification/review-packet?offset=0&limit=100` 为只读、分页审核导出，不请求外部接口，不创建或批准映射。每页最多 200 个候选组。继续读取 `next_offset`，直至 null；不要把第一页当全部覆盖。

每组同时提供候选链/合约身份、准确市场与客户端原生币种 ID、现货/永续类型、合约单位、当前映射、目录指纹以及完整证据来源字段、摘要、观察/到期时间和冲突原因。核对源页面/公开注册表与这些字段一致，不能仅凭 ticker 同名合并，不将现货注册表证据直接扩展到永续。

`ready_proposal_groups` 仅表示代码门槛通过的待审核候选，**不等于已确认覆盖**。`actual_comparable_cross_venue_groups/markets` 来自当前活跃目录的身份门槛；排除未批准、冲突、过期和同平台组。它也不证明价格新鲜、报价币可兑换、存在深度或可盈利。`actual_groups` 展示列表受 limit 限制，截断会显式标记；总计不截断。

审核后选定确实通过的 evidence IDs，重新调用既有 `/preview` 获取该选择的 token，然后使用 `/apply` 原子应用。`page_ready_selection` 附有本页全部 ready 组对应的精确 token，仅在确实审核完本页全部这些证据时使用；其他选择必须重新 preview。目录、证据或冲突变化会使 apply 拒绝，不应自动重试跳过复核。已有 `/revoke` 保留撤销与审计。

2026-11-04 本工作环境只读核查 `data/monitor.sqlite3`：目录 0、证据 0、映射 0，因此没有在此环境应用任何真实资产映射。父线程曾观测的 Gate/Bitget 199 组、440 个现货候选不在此数据库中，不可当作本地已确认覆盖。需在拥有那份真实目录和新鲜证据的运行环境导出审核包，复核后应用，再记录实际组数、市场数及逐平台限制。测试中的多平台小币种为合成夹具，不能计入真实覆盖。

审核包的候选、展示字段和本页选择 token 均从同一次读取的目录、证据与时间构建；生成本页 token 时不会再读取更新后的数据库。展示期间发生的目录/证据变更仍需在 apply 时重新校验，旧包不能批准未展示的新状态。回归通过读取期间提交不同目录和新证据，验证包仍绑定原展示内容且实际 apply 拒绝旧 token。

## 保守批量核验与隔离演练

新增 `GET /api/assets/verification/batch-plan` 只生成 `official-spot-contract-v1` 计划；`POST /api/assets/verification/batch-apply` 接收精确 `plan_token`，仅显式调用时应用该计划的全部合格证据。它不是后台自动批准开关。应用在数据库写事务内再次检查策略和当前状态；目录、证据、源请求结果或有效期变化可能拒绝旧计划，必须重新审阅。原 `/revoke` 按应用返回的 evidence IDs 撤销，保留审计。

批量门槛比普通候选预览严格：至少两个已审阅官方客户端的活跃普通现货市场；原生币种 ID 与官方注册表精确对应；同一明确链和合约地址、单位为 1、完整来源摘要与记录完整性；证据观察不超过 24 小时且至少剩余 1 小时有效期，最新官方请求必须成功并对应该证据收取时间。存在冲突、多链含义不明、缩放代币、人工证据、来源不可用或已有受保护映射时不自动覆盖。永续底层不能由现货资料推断；新增平台需先审阅其客户端和字段语义，不能只加 ticker 白名单。

在拥有真实目录的环境，先运行以下命令（仓库根目录）：

```sh
.venv/bin/python scripts/rehearse_identity_batch.py \
  --source-db data/monitor.sqlite3 \
  --report /tmp/identity-batch-rehearsal.json
```

如官方证据缺失或已过期，可加 `--refresh-public`，仅在临时库收集 Gate/Bitget 公共注册表。原库始终 SQLite `mode=ro`、`query_only`；仅复制白名单目录/身份元数据，不复制账户配置、通知、行情或私密备注。批准与撤销都在自动清理的临时库内发生，报告记录覆盖前后及撤销后、来源状态、候选阻断原因、源元数据摘要。运行时外部采集程序可能合法修改原库，摘要改变需区分这种并发变化，不能直接归因于脚本写入。

官方字段依据：[Gate currencies](https://www.gate.com/docs/developers/apiv4/en/spot/#query-all-currency-information) 明确列出 `chains.name` 与 `chains.addr`，无需认证。Bitget 已配置 `/api/v2/spot/public/coins` 的 `coin`、`chains.chain`、`contractAddress`；本次文档旧路径重定向 UTA，当前 catalog 页面在网页工具不可读取，未据此扩大产品范围。KuCoin 与 Coinbase Exchange 保留各自明确客户端范围，未由 Gate/Bitget 演练推断其真实可用性。

本云环境交易所主机仍受网络策略限制，且本地目录为空。父线程真实 199 组/440 市场候选仍只是候选，实际批准覆盖仍按其 3 组观察记录；不能用合成回归或空库演练替代真实数据演练。后续在持有原数据的环境执行上述只读隔离流程，先核对合格/阻断组及撤销恢复，再决定实际映射应用；任何身份覆盖增长均不替代盘口、报价币、资金费和 24 小时稳定性验收。

批量策略以整个候选身份组为单位保守处理：若同组混有人工或本地池身份资料，该组留待人工审核，不悄悄选取有利证据绕过冲突。它可能降低本批合格数量，报告应解释阻断原因。已有显式映射即使未核验或已过期也受保护，不自动覆盖人工选择。已撤销/被更新取代的历史记录保留审计，不进入当前批量证据选择。

本批演练证据：[合成官方结构夹具](evidence/identity-batch-synthetic.json) 为 0→1→0 个身份组（2 个现货市场），同名同地址异链拒绝；[真实本地空库](evidence/identity-batch-empty-local.json) 为 0→0→0，不能证明外部 199 组可批准。两者来源标签明确分开。
